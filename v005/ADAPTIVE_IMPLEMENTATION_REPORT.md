# 動的初期設計・変数集中探索の実装

初期設計、配分集中、一時固定を個別に有効化できる機能を追加した。3フラグの既定値はON。設定がない場合も有効になり、明示的に3フラグOFFを指定した場合は従来の経路を使用する。既存の工程trialの実測・予測ファイルは変更していない。

## 変更内容

- `focus_config.py`：独立した有効化設定、総予算、出力ごとの許容作用、固定禁止変数、分析上限を検査する。
- `experimental_design.py`：空データから水準被覆と距離に基づく条件を推薦し、操作変数だけの配置・rankを診断する。
- `parameter_focus.py`：一次・二次項の小さな補助回帰をNumPyで計算し、品質制約を含めて配分・一時固定・解除を判断する。水準の対比実測と複数背景、現在の良い条件の背景を要求する。
- `workflow.py`・`optimizer.py`：初期条件と確認条件を通常の推薦CSVで公開する。初期の予測値は空欄とし、シミュレータを呼び出さない。確認候補を改善EIとは別基準で選ぶ。全入力列と既存Hybridを維持する。
- 履歴：同じデータの再実行、データ訂正、流入状態・固定値・設定の変更を区別する。総予算をリセットしない。
- GUI：保存runに対応する変数状態と探索範囲を表示する。過去の表示はその時点のmetadataを読む。

Lunaが初期設計・設定・GUI・文書・基礎テストを分担し、主担当が中核処理、統合、固定成立と解除の追加テスト、実CLI確認を実施した。

## 実際のCLI確認

保存先：`benchmarks/results/adaptive_smoke_20261010/`。これは合成問題の機能確認で、電気接続の物理工程の比較試験ではない。

3操作変数、各4水準、目的値と品質制約を持つ問題を使用した。zだけは測定器の式に影響しない。最適化器と測定器を別のPythonプロセスで起動し、CodexがJSON/CSVを接続した。ファイル接続コードは両プロセスをimport・起動しない。

| 確認事項 | 結果 |
|---|---|
| 初期段階 | 目安12条件から配置の確認を延長し、16条件で探索へ移行 |
| 一時固定 | 実測23条件のrunでzを固定し、主探索を3変数から2変数へ限定 |
| 重要変数 | xとyは探索対象に保持 |
| 最良実測値 | 10.036666666666667 |
| 終了 | 26条件で有用な推薦がなくREVIEW_REQUIRED。設定した総予算40を使い切ってはいない |
| 全域収束 | 宣言していない。限定範囲・全空間の完全性を区別 |
| GUI | 新規8予測runの読込・Tk操作・3D描画のsmoke確認に合格 |

詳細は`summary.json`、各runのmetadata、独立プロセスのログと交換JSONに保存した。結果を予測精度の改善や電気接続の自動収束改善の証拠とは扱わない。

## 検証と残る範囲

既存の機能OFF時の検査、新規の初期条件・予算・影響評価・固定成立・解除・カテゴリ保留・Hybrid不一致の再確認・候補総予算の検査を含む94テストに合格した（デフォルトON・明示OFF・新規trialの設定も確認）。小さい有限空間を測り切った場合の初期段階終了と、同じ設定で初期段階へ戻らないことも確認した。実行記録は`benchmarks/results/adaptive_unittest.log`。既存trialのGUI確認記録は`benchmarks/results/gui_legacy_smoke.log`。
