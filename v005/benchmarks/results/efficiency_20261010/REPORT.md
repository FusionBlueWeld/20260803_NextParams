# v005 改善実装の軽量検証

保存済みの予測を使った推薦方針の再評価と、3 seed の短い実探索を確認した。以前の trial データ・予測面は変更していない。

## 保存予測による再評価

当時までの実測と、当時保存された NN・Hybrid 平均、標準偏差、GP 支持度を新しい optimizer に渡した。再学習や未来の測定値の投入はしていない。

|確認した場面|旧推薦数|新推薦数|確認結果|
|---|---:|---:|---|
|組立 run 17～20|各5|各5|旧推薦で実際に不合格だった20点をすべて除外。新推薦はいずれも予測合格確率5%以上|
|単工程レーザー run 7|5|5|真の格子最適値を発見した旧1位を新1位で保持し、旧不合格4点は除外|
|単工程レーザー run 8|5|1|無理に5件を埋めず、改善候補1件に縮小|
|電気接続溶接 run 1|5|5|初期合格0件でも探索を閉じずに継続|

レーザーのスパッタは整数の順序尺度である。実測の合否は `level <= 4` のまま、予測確率の計算は連続性補正で4.5を境界とする。run 7の実際の最適条件は、旧連続判定の確率1.04%から新判定50.93%となり、絶対確率のフィルタによる機会損失を防げた。連続量の制約境界を緩めた変更ではない。

新たに選び直された未測定の点の真値は未知である。「旧不合格点を避けた」ことを「新推薦がすべて合格した」とは扱っていない。可変件数1件・0件、初期合格0件、候補が指定件数より少ない場合、順序尺度と連続量の違いの7境界テストも合格した。

詳細は `historical_replay.json` と `laser_boundary_review.json`。

## 3 seed の実探索

単工程プレスの元の問題・独立シミュレータを使用した。各 seed で共通の初期12条件から開始し、合計32条件を上限として、uniform random、NN-only、Hybrid を比較した。全候補1521、学習条件上限64、NN ensemble 2、最大300 epoch、学習時間上限10秒。学習は逐次、BLAS は1 thread とした。

optimizer とシミュレータは別プロセスで実行した。Codex が条件 JSON と測定 JSON を渡し、標準ライブラリだけの ingest が CSV に追加した。request SHA-256、測定順序、入力条件の重複なしを全9 case で確認した。格子最適値は探索後の集計だけで参照した。

|seed|方式|最終最良バリ高さ [mm]|格子最適値への初到達|
|---:|---|---:|---:|
|11|random|0.02063194|未到達|
|11|NN-only|0.02063194|未到達|
|11|Hybrid|0.02000000|24測定目|
|29|random|0.02128194|未到達|
|29|NN-only|0.02065000|未到達|
|29|Hybrid|0.02065000|未到達|
|47|random|0.02044444|未到達|
|47|NN-only|0.02000000|23測定目|
|47|Hybrid|0.02000000|23測定目|

Hybrid は2/3 seed、NN-only は1/3 seed、random は0/3 seedで最適値に到達した。追加測定の制約違反はモデル方式では0件、randomでは1件。seed 29の初期違反1件は3方式に共通する。

NN-only は同じ学習済み ensemble を用い、GP の平均補正を使わず、ensemble のばらつきと観測点の残差 RMSE を不確実性に使った。NN-only の実行時間にも比較のため共通で実行した GP 学習の費用が含まれる。純粋な NN 学習費用と GP 追加費用の比較ではない。

これはノイズなしの低次元1問題・短予算の動作確認である。高次元工程・複数の流入状態への一般化や統計的な優位性の証明はしていない。

## 計算資源

9 case で合計288条件を測定した。36回の推薦 worker 内の学習・候補評価の合計時間は2.82秒、CPU時間は2.52秒、worker の最大 resident メモリは39.63 MiBだった。Python起動、Codexの値受け渡し、独立シミュレータの起動・待ち時間は含まない。

Python 3.12.2、NumPy 2.5.1、Windows 11。資源設定・数値・ソースのハッシュは `environment.json`、各 worker は `steps/step_NNN/runtime.json`、全結果は `summary.json` に保存した。

再実行コード：`v005/benchmarks/efficiency_validation.py`。
