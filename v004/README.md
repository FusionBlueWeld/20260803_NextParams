### 処理の読み順と公開条件

1. `cli.py` で `--new`・`--prepare`・`--run` の入口を確認します。
2. `trials.py` → `trial_inputs.py` で入力ファイルと既定値の扱いを確認します。
3. `workflow.py` の番号付きコメントを追い、`hybrid/` の学習・推薦処理を読みます。
4. `diagnostics.py` と `stopping/` で、推薦を出さない条件を確認します。
5. `hybrid/reporting.py` と `stage_bundle.py` で公開される成果物を確認します。

```text
CSV・任意設定 → 共通の入力検査 → 現在の流入状態に固定した候補
                                      ↓
                             学習前の必須停止判定
                                      ↓
                          Hybrid学習 → 推薦条件の計算
                                      ↓
                   NN・Hybrid・実測の必須知識ルール診断
                                      ↓
                     解空間・停止履歴保存 → 推薦公開 → bundle保存
```

`trial_inputs.py` はprepareとrunの共通処理です。実験CSVの内容はrun時に検査します。
広域の流入状態データは学習に使い、現在の流入状態に一致する実測を改善基準にします。
必須知識ルールに違反・未検証があれば新しい推薦を公開せず、前回の推薦は履歴で確認できます。

## 連結用3工程の個別閉ループ検証（2026-09-08）

塗工・乾燥・硬化をそれぞれ独立したv004 trialとして、3 seed×15反復で物理oracleへ戻す
閉ループ検証を実施しました。異なる流入状態の広域データはモデル学習に使いつつ、現在の
流入状態と一致する実測だけを改善基準とし、候補の重複は現在context内の操作条件で判定します。

- 塗工: 3/3 seedで真のグリッド最適点、最大held-out NRMSE 1.33–1.87%。
- 乾燥: 3/3 seedで真のグリッド最適点、最大held-out NRMSE 3.22–4.92%。
- 硬化: 広域128点では最適点に到達しても最大NRMSE 13.2–15.8%で不合格。広域512点へ増やすと
  3/3 seedで最適点、最大NRMSE 7.55–8.82%、制約分類精度99.3–99.7%となり合格。

最終9 trialの統合結果は
[`stage_closed_loop_final_validation.json`](../validation/multistage/results/stage_closed_loop_final_validation.json)
に保存しています。`gp_support`と制約確率は別指標であり、後者は依然として
`UNCALIBRATED_MODEL_PREDICTIVE_ESTIMATE`です。

## 目的

v004は、[v003](../v003/README.md)までの単一工程最適化を維持しながら、個別工程の
流入状態に条件付けて学習・予測できるようバックエンドを拡張し、予測モデルと予測空間を

## v003互換を優先する実装仕様

現場が利用しているv003の操作を標準として維持し、工程接続が必要な案件だけ追加設定を
使います。バックエンドの拡張を理由に、通常案件の入力や操作を一律に変更しません。
ここでいうフロントエンドは、現在のCLI、CSV、表示メッセージ、trial運用を指します。

| 対象 | 実装要件 |
|---|---|
| CLI | `main.py`からの`--new` → `--prepare` → `--run`、既存オプションと既定値を維持する |
| 既存入力 | v003の`problem.csv`、`data/experiments.csv`、知識・探索・停止設定を変更せず受け付ける |
| 通常案件 | 接続設定なしで実行可能とし、既存parameterを操作条件として扱う |
| 既存出力 | 既存CSVのファイル名、列順、列名、意味とrun対応を維持し、接続用成果物は別に保存する |
| 表示 | 日本語の操作案内、推薦理由、警告、停止判断の見方を維持する |
| 接続案件 | 別の任意設定で流入状態、接続用出力、供給元などを宣言する。形式・名称は別途決定する |

### 操作互換と計算互換

追加設定がない場合はv003相当の計算経路を使用し、同じデータ・設定・乱数seed・実行環境で
推薦条件、順位、停止判定を再現します。数値の比較許容差は回帰テストで明示します。
新しい不確実性計算へ無条件に切り替えません。接続機能の有効化と計算方式は設定・履歴へ
記録し、拡張時には結果がv003と異なり得ることを表示します。

v000〜v003は比較基準として原則固定し、v004は独立したスナップショットとして実装します。
明確な不具合の修正は、互換拡張とは分けて変更内容と検証結果を記録します。

### trial移行と日常操作

導入担当者が既存trialの入力・設定をv004側のtrialへコピーし、原本と既存出力を保持します。
v003のrun履歴をv004の計算履歴として扱わず、移行元と新しいrunの対応を記録します。
コピー・移行の具体的な操作は実装時に定義します。

移行後の日常操作は、バージョン指定以外の変更を不要にする方針です。以下は実装後の例で、
共通`main.py`はv004を受け付けます。

```powershell
python main.py --version v004 --run trial_003 --n 3
```

接続設定は導入担当者が準備し、流入状態は上流記録からの取得、案件の固定値、必要時の
現場入力を使い分けます。必要な状態が欠けた場合は、該当処理で不足項目を表示し、
黙って既定値や予測値で補いません。r用の分布伝播やbundle構造を日常操作へ露出させません。

### バックエンドの拡張範囲

- 操作条件と流入状態をともに学習入力とし、個別推薦では操作条件だけを探索する。
- 既存のmonitorも活用し、局所目的に使わない接続用出力を学習・予測する。
- 支持域は操作条件と流入状態の組み合わせで判定する。
- 学習時の正規化、変数順、単位、適用範囲、モデル版を予測器と一緒に保存する。
- 工程ばらつき、モデル不確実性、測定誤差を識別する契約を設け、出力間相関の表現を検討する。
- 拡張経路では、反復平均だけでなく同一製品の出力対応、ロット、測定情報を必要に応じて保持する。

入力欄の追加だけでは流入状態への応答は学べません。既存trialは学習した流入状態の範囲に
利用を限定し、変更後の流入状態を扱うには追加実験が必要な場合があります。
v003の`hybrid_std`は工程ばらつきとしてそのまま流用せず、由来と未分離の要因を明記します。

### 段階実装と受け入れ条件

1. 既存trialによるCLI・入力・出力互換と、推薦・停止判断の回帰テストを成立させる。
2. 入力役割、接続用出力、条件付き平均予測を追加し、oracle接続と学習モデル接続を別々に検証する。
3. 不確実性の種類と同時サンプリング契約を追加し、独立した検証データで予測確率を検証する。

互換テストには知識設定、禁止・優先領域、停止判定、反復測定、monitorを含む既存案件を使います。
拡張テストでは流入状態を勝手に最適化しないこと、不足入力と支持域外を検出すること、
予測器の保存・再読込後に同じ予測を得られることを確認します。
平均予測のみの段階では、最終仕様の予測判定を提供し、良品確率を算定済みとは表示しません。

以前のロードマップにあった「明示的な物理式アンカーをv004へ導入する」構想は削除します。
技能者知見を予測の戻り先にする知識アンカーはv003で実装済みです。具体的な物理式を
組み込む機能は、必要性が明確になった場合にv004とは別の候補として再検討します。

```text
v003の単一工程最適化
  + 工程変数の共通記述
  + 予測平均・不確実性・データ支持度
  + 条件付き一括予測インターフェース
  + rシリーズ向けstage bundle
  = v004（暫定）
```

## 実装済み接続設定と出力

trial直下の任意ファイル`stage_connection.json`で接続機能を有効化します。`controls`と
`incoming_context`は`problem.csv`のparameterを重複なく全て分類し、現在の流入状態を
`current_incoming_context`へ明記します。不足値、余分な値、非有限値、適用範囲外はエラーです。

```json
{
  "schema_version": "1.0",
  "stage_id": "coating",
  "controls": ["coating_gap_um", "line_speed_m_min", "web_tension_n"],
  "incoming_context": ["incoming_viscosity_pa_s"],
  "connector_outputs": ["wet_thickness_um"],
  "current_incoming_context": {"incoming_viscosity_pa_s": 1.6}
}
```

接続設定があるrunでは流入状態を固定し、controlだけの候補を推薦します。既存出力に加えて
`output/stage_bundles/stage_bundle_run_####/`へ変数定義、manifest、予測器、能力、provenanceを
保存します。予測器は入力範囲と全項目を検査し、各出力の平均・標準偏差、支持度を返します。
pickle予測器は信頼できるローカルbundleだけを読み込んでください。

検証結果は[`v004_connected_production_validation.json`](../validation/multistage/results/v004_connected_production_validation.json)にあります。
96件の流入状態付き塗工oracleデータで、27候補の流入値固定、全8出力の最大NRMSE 0.0322、
保存・再読込差0を確認しました。通常案件は同一seedのv003/v004 15反復履歴が完全一致します。
互換比較の要約は[`v003_v004_compatibility.json`](../validation/single/results/v004/v003_v004_compatibility.json)に保存しています。

## v004の責務

v004は一つの工程だけを担当します。工程全体の順序や、どの出力を次工程へ接続するかは
決めません。

- 実験データから個別工程モデルを学習する
- 個別工程のBest条件を推薦する
- 条件ばらつきを定義できる場合、個別Robust条件を算定する案を検討する
- 目的値以外を含む全予測出力の平均・不確実性を返す
- 実測データによる支持範囲、外挿、制約適合確率を明示する
- rモデルが条件と流入状態を与えて一括予測できる共通の口を提供する
- モデル、変数定義、予測空間、履歴、provenanceをstage bundleとして書き出す

個別Robust推薦は初期の互換・平均接続段階の必須機能にしません。rモデルが全体良品確率を
計算する段階では、意味を定義した不確実性と相関・サンプリングの契約が必要です。

## 変数の共通記述とv側の役割

変数名、意味、単位、型、適用範囲はv/r共通の定義として持ちます。その上でv004は、
個別工程内での利用方法だけを記録します。

| v側の役割 | 意味 |
|---|---|
| `control` | 自工程で操作できる条件 |
| `incoming_context` | 原料、環境、上流状態など、与えられた条件 |
| `predicted_output` | vモデルが予測する出力 |
| `local_objective` | 個別工程の最適化対象 |
| `local_constraint` | 個別工程内の制約 |
| `monitor` | 予測・記録するが通常は個別最適化に使わない指標 |

一つの変数は複数の役割を持てます。例えば乾燥膜厚はv004では`predicted_output`かつ
`local_constraint`であり、r001では下流へ渡す接続状態になる場合があります。

## Bestと接続出力の関係

個別工程のBest目的値が、そのまま次工程に必要とは限りません。例えば塗工工程の目的が
処理量最大化でも、乾燥工程が必要とするのは湿潤膜厚、固形分率、膜厚変動、欠陥状態です。

そのためv004はBest条件とBest目的値だけでなく、その条件における全予測出力と、任意の
条件で再評価できる予測器を公開します。r001は必要な出力だけを選んで接続します。

## stage bundleの暫定案

```text
stage_bundle/
├─ variables.json              名前、意味、単位、型、適用範囲
├─ stage_manifest.json         v側の役割、目的、制約、モデル版
├─ predictor/                  保存済み予測器または共通予測API
├─ response_spaces/            runごとの予測空間
├─ recommendations.csv         Best／Robust候補
├─ uncertainty_schema.json     平均、分散、相関、支持度の定義
└─ provenance.json             データ・設定・ソースの識別情報
```

静的なBest行やCSVだけでは、r001が接続状態に応じて条件を動かせません。stage bundleは
少なくとも次の概念的な呼び出しを提供する必要があります。

```python
prediction = stage.predict(
    controls={"air_temperature_c": 92, "residence_time_min": 7},
    incoming_context={"wet_thickness_um": 162},
)
```

返却候補は、各出力の予測平均、標準偏差、制約適合確率、データ支持度、補間／外挿区分です。
出力間の相関をどう保存・近似するかは未確定です。

bundleはスキーマ版、計算方式、流入状態の支持域、提供可能な予測能力を明示します。
能力は平均予測、不確実性の内訳、同時サンプリングなどを区別し、未対応項目を0や独立と
みなしません。既存trialから作成できても、確率伝播対応を自動的に意味するものではありません。
