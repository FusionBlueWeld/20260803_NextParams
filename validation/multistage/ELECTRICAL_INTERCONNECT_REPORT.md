# v005 / r002・Cu/Al電気接続ラインの実装検証

NumPyと標準ライブラリだけで、6加工ノードの接続・予算付き探索・下流再調整・
在庫実験・測定追加と再学習を実装しました。**計算量と実装契約の検証は通過しています。
全工程の学習予測だけで良品条件を安定して見つける精度基準は、今回まだ満たしていません。**

## 検証したもの

CuとAlを別々に切断・成形し、組立で合流してレーザー溶接へ渡します。
最終検査は溶接後の電気・寸法検査と別試片の破壊検査です。
工程の物理構造・文献・係数の仮定は[物理モデルの説明](electrical_interconnect/README.md)を参照してください。

| 加工ノード | 操作数 | 流入状態数 | 4水準の操作格子 |
|---|---:|---:|---:|
| Cu切断 / Al切断 | 各7 | 各7 | 各16,384 |
| Cu成形 / Al成形 | 各7 | 各13 | 各16,384 |
| 組立 | 8 | 42 | 65,536 |
| 溶接 | 8 | 26 | 65,536 |

全操作は44軸です。`4^44 = 309,485,009,821,345,068,724,781,056`条件の直積は
生成しません。4,096条件の物理監査では切断後の良品がCu3,869／Al3,867、
両成形を通った組立入力が318、組立を通った溶接入力が195でした。
下流学習へ上流NGや範囲外の状態を渡さず、加工していない下流の正解ラベルを追加しません。
Cu/Al・Cu/Cu・Al/Alを物理監査し、学習模型の閉ループはCu/Alを対象にしました。

## 模型・探索の変更

v005はv004の通常NN・GP・知見機能を独立して継承し、流入状態を候補生成前に固定します。
大きな操作空間は有限点を抽出し、学習点数・候補数・学習時間にも上限を設けます。
新しいbundle 2.0はJSONと数値NPZで、変数の役割・単位・適用範囲・支持度を検査します。
通常CLIの模型と、高速な固定隠れ層NN＋残差カーネルの工程APIを分けています。

高速模型では実際に観測した入力の中心と変動尺度を使います。例えば隙間の宣言範囲が
0～5 mmでも、合格ワークの変動は0～0.15 mmに限られ、全範囲の尺度だけでは感度を
捉えにくいためです。適用範囲判定は物理boundsを維持します。
最大角度・最大隙間・合計抵抗の既知の数量関係も宣言し、別々の回帰による矛盾を防ぎます。
派生出力は点予測を整合させる処理であり、厳密な同時分布の期待値ではありません。

r002は工程ID付きの操作名とDAGを使い、毎候補の上流状態を下流へ伝えます。
LHS、差分進化、工程ごとの変更、全工程の共同変更を予算内で比較します。
実施済み操作を固定した再探索、局所受入照会、明示的な組立ペアと在庫を使う部分実験に対応します。
加工による消費と検査の破壊性を区別し、非破壊検査でも同じ加工前ワークを複数条件に割り当てません。

## 3乱数条件の結果

各seedで8,192製作条件を抽出し、工程ごとに最大256学習点を保持しました。
別seedの4,096製作条件を予測誤差の採点に使っています。基本の探索は2,048ライン評価、
64条件の集団、64行のバッチ、支持度閾値0.5です。
正解関数の大予算探索は8,192評価で、模型へその正解を返していません。

| 評価方法 | seed 0 | seed 1 | seed 2 |
|---|---|---|---|
| 学習模型のr002：予測上の合格 | 未発見 | 合格予測 | 未発見 |
| その推薦を独立oracleで採点 | NG | NG | NG |
| stdを1倍減算する保守設定 | 未発見 | 未発見 | 未発見 |
| 同じ学習模型・同じ件数のランダム選択：oracle合否 | NG | NG | NG |
| 局所oracle Bestを順につなぐ参考法 | NG | NG | NG |
| 大予算oracleの全工程探索 | 合格 | 合格 | 合格 |
| 上流を完全観測して残り工程を再調整 | NG | NG | 合格 |
| 既知良品の系譜を保持して探索：oracle合否 | NG | 合格 | NG |

保守設定は誤合格を抑えましたが、合格条件も発見できていません。校正済み信頼区間や
良品確率を表す設定ではありません。seed 1の通常模型とseed 2の履歴起点模型には
予測合格・oracle不合格があり、その結果を削除せずJSONへ保存しています。

履歴起点の方式は、実験済みの良品レシピを最大4つ保持し、同じ系譜の学習行を
6モデルの間引きで失わないようにします。既知条件の再現は新しい最適条件の発見と区別します。
上流完全観測の再調整も大予算oracleの候補を起点にした上限比較であり、模型自身が
見つけたワークの回復実績としては扱いません。

各seedで4回×4条件の確認実験を行い、実際に加工した工程の結果だけ追加して
最大3回再学習しました。48製作確認の範囲では新しい合格レシピに届きませんでした。
別の未溶接在庫による部分実験では、各seedで3ワークを測定・消費し、溶接模型を更新して
再探索しました。追加測定の保持、データhashの変化、消費済みワークの除外を確認しています。
再学習が行われたことと、予測精度が改善したことは別の判定です。

## 実行負荷とテスト

Python 3.12.2 / NumPy 2.5.1、BLAS 1スレッドで、上記3seedの全検証は約64.8秒でした。
tracemallocの最大割当は約78.9 MBです。これはPython／NumPyの計測対象割当であり、
プロセス全体のRSSや16 GB PCの性能保証ではありません。
通常r002 CLIでは、保存済み6模型のprepareと2,048評価のrunが通り、runは約0.42秒でした。

16入力・6出力の独立した計算負荷試験では、512点の高速模型学習・保存が約0.090秒、
4,096点予測が約0.173秒でした。これは製造物理の精度試験ではありません。

- validation：127テスト合格。既存100件、新しい物理19件、結合8件。
- r002：22テスト合格。分岐合流、単位、予算、観測・仮想状態、在庫消費、std検査など。
- v005：15テスト合格。候補生成前固定、保存一致、尺度、派生関係、通常CLIなど。

合計164件です。異方的な合成関数では、観測尺度を使う模型のheldout MAEは0.00360、
固定尺度対照は0.10430でした。この単体改善を、製造ライン全体の精度達成とは扱いません。
最終JSONはsource hashと実行中のsource不変確認を含みます。

## 現時点の限界

この模型検証は、シミュレーション内部状態のラベルを使う完全情報の条件です。
現場の検査APIは潜在状態を返さず、部分観測の結果は
`UNKNOWN_WITH_UNOBSERVED_STATE`と記録します。部分観測の潜在状態推定、出力相関を
含む誤差伝播、校正済み良品率、最終検査noiseの校正は未達です。

組合せ爆発は避けられますが、限られた工程データから連結状態を正確に予測できる
問題とは別です。条件付き予測の支持域と誤差、状態間の整合、部分観測下の模型を
さらに改善する必要があります。この初版を実設備のレシピ・品質判定に直結できる
精度検証済みモデルとは扱いません。

## 再現方法と成果物

新しい保存先で実行します。`workdir`をr002 trial名にすると、先頭seedの設定が親にも作られます。

```powershell
python -m validation.multistage interconnect audit --samples 4096
python -m validation.multistage interconnect benchmark `
  --workdir r002/trials/trial_interconnect_review --samples 8192 --budget 2048 `
  --sample-cap 256 --seeds 0 1 2 --output validation/multistage/results/interconnect_review.json
python main.py --version r002 --prepare trial_interconnect_review
python main.py --version r002 --run trial_interconnect_review --n 3
python -m unittest discover -s validation -t . -v
python -m unittest discover -s r002/tests -v
python -m unittest discover -s v005/tests -v
```
