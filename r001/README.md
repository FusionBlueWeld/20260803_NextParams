# Process Relation Optimizer r001

> **ステータス: 現行機能範囲でFIX（2026-09-09）**
> 直列工程、明示接続、固定候補、観測可能状態、仕様余裕最大化を実装しています。
> 同時サンプリング契約がないbundleの良品確率は、通常は推測せず`NOT_EVALUATED`と出力します。
> 明示的な`process_variation`設定時だけ工程入力ばらつきの未校正推定を実行できますが、校正済み良品確率ではありません。
> 平均予測接続・連結窓・窓中心選択・同時変更評価の版固定です。検証結果、校正schema 1.1への
> 移行、既知の広域誤許容については[FIX記録](../V004_R001_FIX_RECORD.md)を参照してください。

## 目的

r001は、複数工程で個別に作成・更新された[v004 stage bundle](../v004/README.md)を蓄積し、
工程グラフ上で接続して、最終製品の良品確率と全体条件を調整する別レイヤーです。

```text
v004 塗工stage bundle ─┐
v004 乾燥stage bundle ─┼→ r001 → 全体条件案・最終良品確率
v004 硬化stage bundle ─┘
```

r001はv004の後継スナップショットではありません。vシリーズが個別工程を深く解き、
rシリーズが既存の個別工程モデルを組み合わせる役割分担です。

## v004互換方針に伴う構想更新（2026-09-07）

v004はv003の現場操作を維持し、工程接続を案件ごとの追加設定として導入します。
r001はこの方針に合わせ、個別工程の日常操作を変更せず、導入担当者が工程グラフと
bundleの対応を設定する別レイヤーとします。v003以前の直接修正を前提としません。

### bundleの能力に応じた接続

- 登録時にスキーマ版、計算方式、変数の役割・意味・単位、必須入力、provenanceを検査する。
- 既存trial由来のbundleを、任意の流入状態に対応するモデルとはみなさない。
  操作条件と流入状態の組み合わせで支持域を確認し、不足データと必要な実験を明示する。
- 平均予測のみのbundleでは、平均を伝播した最終仕様の予測判定までを提供する。
  これは最終出力の期待値や良品確率と一致するとは限らない。
- 確率伝播は必要な不確実性・同時サンプリング契約を満たす場合に有効化する。
  能力不足を分散0や独立で黙って補わず、良品確率は未評価と表示する。
- 接続に必要な入力は上流出力または外部状態から供給し、欠落・競合を検出する。
  外部状態や接続先入力を、独立した操作条件として自由に最適化しない。

### 初期範囲と実装順

初期対象は直列3工程、明示接続、固定候補、観測可能状態とします。

1. 共通予測口を持つ決定論oracleで接続し、現行pipelineと中間状態・最終判定を照合する。
2. 各工程を学習済み予測器に置き換え、未学習データで接続後の誤差と支持域判定を検証する。
3. 分布伝播を追加し、独立した検証シナリオで良品確率の精度と推定区間を評価する。
4. 同じ必須制約・候補・評価予算で個別Best連結と全体調整を比較する。

個別Robust連結は対応bundleが用意できた段階で追加します。潜在状態推定と情報価値による
後戻り実験は後続段階です。完全観測かつ期待レシピが既知の場合のNG工程順位付けと
反実仮想回復は、検証器で実験的に評価しています。
以下の責務・構想はこれらの後続段階も含む到達像です。

### CLIとpipeline.json

```powershell
python main.py --version r001 --new trial_line
python main.py --version r001 --prepare trial_line
python main.py --version r001 --run trial_line --n 3
```

`pipeline.json`には順序付き`stages`、`connections`、未接続の`external_context`、全controlの
`candidate_axes`、`final_specifications`を指定します。接続元・先の存在、単位完全一致、入力の
欠落・競合、bundle schemaと平均予測能力をprepare/runの両方で検査します。仕様余裕の尺度は
必要に応じて各仕様の`margin_scale`で明示できます。

runは全固定候補を同じ仮想製品として順に伝播し、`output/system_recommendations.csv`と
`output/run_summary.json`を保存します。初版の順位は最終仕様の最小正規化余裕、同率時は
最小stage支持度です。

`connected_window`を指定すると、各工程の局所制約、接続先入力範囲、最終仕様、stage支持度の
共通部分を連結ウィンドウとして評価できます。区間方式は従来互換の`std_multiplier`、実単位の
`residual_quantile`、予測標準偏差で正規化した`standardized_residual_quantile`から選べます。
残差方式は、学習とは別の校正データで工程・出力・制約方向別に求めた片側残差を使います。
校正ファイルには各bundleのSHA-256を記録し、bundle更新後の古い校正値は受理しません。

選択条件について、平均のみ、誤差バッファ込み、支持度込みの判定、分離した全許容区間、上下
headroom、境界の律速制約・予測平均・標準偏差・支持度を`output/connected_window.json`へ
保存します。これらは9次元領域の一変数断面であり、独立な直方体ではありません。

`window_center_selection`を有効にすると、必須条件を満たす候補から従来余裕と条件空間の多様性を
併用して有限個を選び、各操作の必要変動幅で正規化した最小対称headroom `rho`を最大化します。
評価予算と全候補ではない旨を`run_summary.json`へ、比較結果を
`window_center_candidates.csv`へ保存します。`simultaneous_window`は選択中心の周囲で乱数内部点、
全頂点、律速二変数断面を別途評価し、`simultaneous_window.json`へ保存します。有限標本の結果を
厳密な9次元許容体積とは扱いません。

連結物理検証は[`r001_production_validation.json`](../multistage_validation/results/r001_production_validation.json)に保存しています。塗工→乾燥→硬化の19,683候補で、
全中間接続後の最終11出力が既存pipelineと誤差0、選択候補がoracleの仕様余裕最大候補と一致しました。
個別Best連結は余裕-0.2679で不合格、全体調整は0.4464で合格し、余裕を0.7143改善しました。

### 工程ばらつき確率の実験検証

`process_variation`に各control・外部状態の標準偏差、サンプル数、seed、評価候補数を明示すると、
上位中心条件の同じシナリオ番号を3工程へ伝播し、`robust_recommendations.csv`へ未校正の予測良品率と
Monte Carlo誤差だけのWilson 95%区間を保存します。分布は独立・上下限クリップ正規分布です。
v004 bundleのモデル誤差・出力同時分布・測定誤差は含まないため、状態は
`UNCALIBRATED_PROCESS_VARIATION_ESTIMATE`です。

最初の128点/工程のbundleでは、予測96.68%に対して独立物理oracle 70.92%、校正MAE
0.3857、Brier score 0.2714となり不合格でした。この診断は
[`probabilistic_r001_production_validation.json`](../multistage_validation/results/probabilistic_r001_production_validation.json)
に残しています。

その後、3工程を個別に3 seed×15反復で検証し、予測空間基準に不合格だった硬化だけ広域学習点を
128から512へ増やしました。個別検証済みの代表seed 0 bundleを再接続すると、決定論的な真の仕様余裕は
0.4277、個別Best連結から+0.6955となりました。工程ばらつき評価は予測100%に対して独立物理oracle
99.976%、上位128候補のMAE 0.01936、Brier score 0.00733、全19,683候補基準の選択regret
0.00098となり、定めたoracleベンチマーク基準に合格しました。結果は
[`validated_individual_chain_probability_calibration.json`](../multistage_validation/results/validated_individual_chain_probability_calibration.json)
です。ただしbundle能力上はモデル誤差・出力同時分布を含まないため、表示状態は引き続き
`UNCALIBRATED_PROCESS_VARIATION_ESTIMATE`です。

### 最終予測・NG診断・全工程回復の検証

個別検証済みbundleを使い、学習に使っていない4,096条件を同一製品として塗工→乾燥→硬化へ
伝播しました。学習モデルが接続範囲内と判定した85.16%では、最終合否accuracy 97.76%、
precision 90.40%、recall 75.21%でした。最終出力の最大NRMSEは、真の中間状態を渡す場合4.77%、
予測状態を順送りする場合5.28%で、上流誤差による増分は0.52ポイントでした。

ただし仕様境界から正規化余裕0.1未満ではaccuracy 64.53%まで低下します。余裕0.1以上では
99.49%、0.2以上では99.94%です。従って現版は、接続範囲外を棄却し、境界付近を確定判定せず
追加測定へ回す条件付き予測器として扱います。支持度0.5以上かつ予測余裕0.2以上をOK判定に
使った検証では21件すべて物理oracleでもOKでしたが、この件数だけで実機保証とはしません。

既知原因4ケースは原因ラベルを診断器へ渡さず、工程内制約の満足確率、期待レシピへ工程単位で
戻した場合の最終余裕改善、各工程だけ／全工程の条件探索を評価しました。単一原因3ケースは
正しい工程が改善量1位、複合原因ケースは3工程すべてが正の改善量になりました。全4ケースで
最小変更案が物理oracleを正常化しました。故障条件を固定した補償では、塗工gap故障は乾燥時間、
乾燥滞留時間故障は乾燥温度の変更で回復できましたが、硬化温度故障と4工程ドリフトは他条件で
補償できませんでした。

結果は[`r001_diagnostic_validation.json`](../multistage_validation/results/r001_diagnostic_validation.json)、
再実行コードは[`r001_diagnostic_validation.py`](../multistage_validation/r001_diagnostic_validation.py)です。
工程内制約確率は「NGの発現箇所」、反実仮想改善量は「調整候補」であり、物理原因の事後確率
ではありません。また現bundleに多出力同時サンプルと工程間モデル誤差相関がないため、校正済み
end-to-end不良確率は未完成です。

連結後の独立校正4,096点と方式選択用4,096点を分け、偽陽性0を満たす候補のうち真陽性最大となる
正規化片側残差分位方式（片側`alpha=0.15`）を採用しました。最終trialでは19,683候補中215候補が
連結条件を満たしました。選択中心の物理oracle最終仕様余裕は0.3611、9操作軸断面の危険側
はみ出しは0、平均oracle窓回収率は80.7%（旧方式35.9%）でした。2,174走査点の混同行列は
TP 1,260、FP 0、FN 223、TN 691です。

必要変動幅に対する対称余裕`rho`は、従来の連結余裕中心の予測0.75／oracle 1.9167から、
窓中心選択で予測2.5／oracle 2.7917へ改善しました。ただし96/215候補の予算付き探索であり、
上位8候補のoracle再評価では予測7位にoracle `rho=3.3333`の候補もあるため、大域最適とは
表示しません。同時変更では`rho`箱の一様乱数4,096点中、予測3,815点・oracle 3,903点が合格し、
FP 0、FN 88でした。全512頂点は予測338点・oracle 440点が合格し、ここでもFPは0でした。
詳細は[`connected_window_validation.json`](../multistage_validation/results/connected_window_validation.json)と
[`window_center_joint_validation.json`](../multistage_validation/results/window_center_joint_validation.json)です。

## r001の責務

- stage bundleを登録し、互換性とprovenanceを確認する
- 工程順序と、上流出力から下流入力への接続を定義する
- 各工程の予測分布を、同じ仮想製品・シナリオとして後工程へ伝播する
- 個別Best連結、個別Robust連結、全体調整条件を比較する
- 各工程の許容領域とデータ支持範囲を守って全体条件を調整する
- 最終目的、最終制約、良品確率、コスト、処理量を評価する
- OKゾーン移動、工程別感度、NG原因候補を診断する
- 情報不足の場合、追加実験へ戻る工程と条件を提案する構想を検討する

## r側の役割

v004の役割一覧とr001の役割一覧は一つに統合しません。変数の意味・単位・型だけを共有し、
r001は工程全体での使い方を別に定義します。

| r側の役割 | 意味 |
|---|---|
| `connector_source` | 下流工程へ渡せる予測出力 |
| `connector_target` | 上流工程から受け取る入力 |
| `system_control` | 全体調整で変更可能な工程条件 |
| `system_objective` | 工程全体の最適化対象 |
| `system_constraint` | 最終製品または全体運用の制約 |
| `external_context` | 原料ロット、環境、設備状態など外部から与える状態 |
| `observable_state` | 実工程で測定できる中間状態 |
| `latent_state` | 物理的には存在するが利用側から見えない状態 |
| `proxy_state` | 潜在状態の代わりに測定する指標 |

同じ変数でも役割は工程グラフごとに変わります。v004側へ接続先を埋め込まず、r001の設定で
必要な出力だけを選ぶことで、同じstage bundleを別の製造ラインでも再利用します。

## 工程接続の暫定案

```json
{
  "stages": [
    {"id": "coating", "bundle": "coating_v004_bundle"},
    {"id": "drying", "bundle": "drying_v004_bundle"},
    {"id": "curing", "bundle": "curing_v004_bundle"}
  ],
  "connections": [
    {
      "from": "coating.wet_thickness_um",
      "to": "drying.incoming_wet_thickness_um"
    },
    {
      "from": "drying.residual_solvent_pct",
      "to": "curing.incoming_residual_solvent_pct"
    }
  ]

```

接続時には名前だけでなく、単位、意味、範囲、予測支持域を検査します。必要な単位変換を
許可するか、完全一致だけを許可するかは未FIXです。

## 尤度と不確実性の伝播

r001は各工程の合格確率を単純に掛け合わせません。上流工程の予測出力を同一シナリオの
状態として下流へ渡し、工程間の相関を維持したまま最終製品の合否を計算する案です。

```text
塗工の予測状態分布
  ↓ 同じ仮想製品の湿潤膜厚・膜厚CV・欠陥
乾燥の予測状態分布
  ↓ 同じ仮想製品の残留溶剤・内部応力・乾燥膜厚
熱硬化の予測状態分布
  ↓
最終仕様を満たすシナリオの割合 ＝ 全体良品確率
```

工程ばらつき、vモデルの予測不確実性、検査ノイズ、ロット・設備ドリフトは可能な限り
別の要因として保持します。どこまで相関を表現するか、Monte Carloと近似計算をどう
使い分けるかは今後の検討事項です。

同一シナリオ番号の維持だけでは出力間相関を復元できません。工程内の複数出力は同時分布
または同時サンプルとして受け取り、共通ロットなどの変動も同じシナリオで共有する必要が
あります。検査ノイズを実物の状態変動として下流へ流さず、モデル不確実性と工程ばらつきを
二重計上しない契約をv004と共有します。独立などの近似を使う場合は仮定と検証結果を記録します。

## 個別Bestと全体条件調整

工程のBest目的値が次工程の接続値とは限りません。r001はBest目的値ではなく、Best条件や
周辺条件でv004が予測した別の出力を接続できます。

```text
塗工の個別目的: 処理量
乾燥への接続値: 湿潤膜厚、固形分率、膜厚CV、欠陥
```

個別Bestをそのまま連結した結果が最終NGになる場合、r001は各工程の制約適合確率、許容性能、
データ支持範囲を満たす領域内で条件を動かし、最終良品確率を優先する全体条件を探します。

設備上限・必須の工程制約は全体探索でも維持し、局所目的や合意した許容性能とは分けて
設定します。局所性能をどこまで譲歩できるかは明示し、最終合格だけで制約違反を許しません。
連続設備では速度と滞留時間・炉長の関係、バッチ設備では容量・所要時間などを定義してから
処理量を評価します。設備制約が未定義の段階では、生産能力まで最適化できたとは扱いません。

現行oracleの仕様余裕最大化は良品確率最大化の比較基準です。確率最適化の成立は別に検証し、
探索に使った乱数とは独立したシナリオでも候補を評価します。

## 接続状態が不明な場合

実工程では接続状態が測れない、または存在自体が分からないことがあります。r001では、
同じ工程グラフに対して観測方針を切り替えられる構想です。

- 完全観測: 検証用にすべての接続状態を利用する
- 部分観測: 測定可能な状態とproxyだけを利用する
- 潜在状態: oracle内部では存在するがr001には渡さない

潜在状態を完全に隠した場合、r001ができるのはOKゾーン移動の検知、条件追従、原因工程の
確率的な順位付けまでで、物理原因を一意に特定できない場合があります。

## 後戻り実験

既存のstage bundleだけでは全体判断の不確実性が大きい場合、次を比較する案です。

```text
追加実験価値
  = 全体判断の不確実性低減
    ÷ 実験費用・時間・停止リスク
```

工程ごとの再実験可否、費用、所要時間、上限回数を設定し、価値の高い工程・条件だけを
個別vモデルへ戻します。これは個別Best探索ではなく、工程接続や最終NG判断の不確実性を
減らすための追加実験です。

## 最初の検証対象

[`multistage_validation/`](../multistage_validation/README.md)の塗工→乾燥→熱硬化oracleを
最初の対象とします。初期接続の完成条件は上記の段階実装で定めます。
次は後続機能も含む到達目標です。

1. 個別Best連結の最終品質を再現できる
2. 全体調整により最終良品確率を改善できる
3. 観測／潜在状態を切り替えて評価できる
4. 既知原因の工程ドリフトを上位候補として診断できる
5. データ不足時に有効な後戻り実験を提案できる

## 検討事項

- 分岐・合流・再加工を後続のどの段階で扱うか
- 予測分布の相関をどの形式で受け取るか
- 全候補探索、シナリオ最適化、動的計画法のどれを使うか
- 全体性能、良品確率、エネルギー、処理量をどう優先するか
