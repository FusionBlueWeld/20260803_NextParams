# 複合工程物理シミュレータ

`functional_coating` は、塗工 → 熱風乾燥 → 熱硬化の3工程を個別モデルとして評価し、`pipeline.py` で工程間の状態を受け渡す検証用ラインです。既存の `validation/` 個別工程検証とは独立したパッケージです。

## v004・r001構想への適合評価と修正方針（2026-09-07）

**直列3工程の状態接続を検証するoracleとして使えます。** 操作条件と流入状態が分離され、
配列の同じ位置を同じ仮想製品として下流へ渡す構造は、新しいv004・r001方針に合っています。
ただし、現在は物理式を直接接続した試験装置で、学習済みbundleの互換性・確率精度・現場の
観測可能性は未検証です。以下は今後の修正方針であり、既存コードに実装済みではありません。
単工程の操作互換は[validation側の評価](../validation/README.md)と分担します。

### 形式・接続契約

| 現状・根拠 | 不一致・不足の理由 | 修正方針 |
|---|---|---|
| `stages.Stage.evaluate()`は操作・流入状態を一つの辞書で受ける | v004の`predict(controls, incoming_context)`と形式が異なる | 物理式を変更せずアダプターを追加し、manifestの`incoming_state`を`incoming_context`へ対応付ける |
| 工程manifestは単位・範囲・局所目的等を持つ | bundleの予測器・正規化・支持域・不確実性能力は持たない | スキーマ版と能力を定義し、oracleアダプターと学習bundleを区別する。oracleを学習器へ渡すのは接続契約の試験時だけとする |
| 接続は`process_manifest.json`と`pipeline.py`に重複記述 | 現在の接続テストだけでは誤配線・単位差・入力競合を網羅できない | 汎用接続器を現行pipelineと全中間値で照合し、欠落・重複供給・意味／単位不一致の負例を追加する |
| 塗工wet_thicknessの宣言出力範囲は0〜300 um、乾燥入力は60〜270 um | 範囲が完全包含ではなく、宣言だけで全域接続可能とはいえない | 実際に到達する状態を候補・シナリオごとに検査する。範囲外を黙ってクリップせず、接続不可と支持域外を区別する |
| `evaluate-line` CLIは原料省略時に基準値を補う | r001の必須流入状態欠落を検出する契約と異なる | 既存CLIは例示・回帰用途として維持し、r接続口では明示した外部状態だけを受け付ける |
| 複合工程にはv004向け学習CSV生成・反復学習接続がない | oracle直結の成功は学習モデル接続の成功を意味しない | 製品・ロット・反復ID、真値と測定値を分離した生成器を追加する。操作＋流入状態で学習し、製品／ロット単位で検証を分離する |

### 採用する物理指標と前提

| 指標・状態 | 評価と修正方針 |
|---|---|
| 湿潤膜厚・乾燥膜厚・最終膜厚 | 接続状態として維持する。測定時点・位置・平均化範囲を定義し、同一試料での対応を記録する。単工程thermal_curingのmmとは明示換算する |
| 固形分率・残留溶剤率 | 質量収支の接続に有用。dryingの式では固形分は質量分率、残留溶剤率は溶剤／（固形分＋残留溶剤）の百分率。manifestに分母・対象物質を追記する。単工程の水分率とは自動対応させない |
| 硬化後残留溶剤率・膜厚 | curingは流入残留率を指数減衰し、膜厚は収縮・圧密で別計算する縮約式。乾燥と同程度の厳密な溶剤質量収支は保証しない。初版は近似を明示し、保存則を検証する版では固形分・溶剤の面積質量から率と膜厚を再計算する |
| 膜厚CV | 接続に有用だが、oracleでは既知値。実測での空間ばらつきと製品間ばらつきは別物なので、測定窓・標本数・誤差を定義する |
| 内部応力・硬化率・劣化率 | 物理状態・品質診断として維持するが、直接観測可能とは未定義。観測契約で直接測定・proxy・潜在を指定する。完全観測oracle試験と現場観測試験を分ける |
| coating/drying/final defect_index、skinning、blister | 検証用の合成指数であり、0〜1でも欠陥確率や実測不良率ではない。初版は合成指標と明示する。観測版では欠陥面積率・個数密度など対象検査を選び、対応式・ノイズ・閾値を別途校正する |
| 接着強度・寸法変化 | 最終仕様として維持できる。試験条件・試料形状を定義し、実機の規格値を検証用閾値と混同しない |
| 乾燥終了時膜温度 | 出力はあるがcuringへ渡らず、curingは周囲温度から昇温する。工程間で冷却される前提の試験として明記する。熱いまま直結する版では流入温度・移送時間／冷却モデルを追加する |
| line_throughput_m2_h | 現行は速度×60で、幅1 m相当の名目面積速度。乾燥・硬化の能力制約を含まない。ライン処理量の評価には幅、炉長と速度、またはバッチ容量・時間を追加する |
| total_thermal_energy_kj_m2 | 縮約式の乾燥＋硬化の面積当たり熱エネルギー。設備全体の電力・待機損失・良品当たりコストではない。初版は比較指標に限定し、対象設備を決めた版で境界と損失項を定義する |

初版は現在の物理指標を全面置換せず、完全観測の合成oracleとして使います。
現場の観測可能状態だけで検証する段階では、測定モデルを定義し、使えない状態をoracleから
黙って供給しません。代理指標で足りない場合は潜在状態を扱う後続試験へ分けます。

### 最適化・確率評価の不足

- `benchmark.individual_best_chain()`は上流Bestの状態を使って下流を順次最適化する比較基準。
  固定された各工程の既存Best行をそのまま連結する試験とは別に扱い、比較方式を記録する。
- 全体候補は現在、最終仕様中心で採点し、個別Bestの局所制約を再適用していない。
  必須工程制約と譲歩可能な局所目標を設定で分け、同じ必須制約の下で比較する。
- `quality_margin`は最小正規化仕様余裕であり、良品確率ではない。余裕最大化を比較基準に
  残し、確率最大化は別の選択処理・独立シナリオで評価する。
- `robustness.py`は独立した入力正規乱数を上下限でクリップする。端点に確率が集まる方式で、
  切断正規分布とは異なる。既存seed回帰用に保持し、新しい試験ではクリップの設備的意味、
  相関・共通ロット変動・範囲外の扱いを宣言した分布を別設定で用意する。
- 検査ノイズとモデル不確実性は未実装。工程変動→oracle真値→測定の層を分け、学習モデルの
  不確実性は学習側が推定する。既知の多出力・共通ロット相関を持つシナリオを使い、
  同一シナリオの維持だけで相関を再現したと判断しない。
- 良品確率は点推定だけでなくサンプル数・seed・推定区間を記録する。512件全合格でも真の
  良品確率100%とは扱わない。モデル不確実性による幅とMonte Carlo推定誤差も分ける。
- `stage_freeze_yield_improvement`は仮想的な変動固定の感度で、原因確率ではない。
  `fault_scenarios.py`は原因ラベル付き条件介入で、潜在設備ドリフト推定の実証ではない。
  後続試験では設定値と実効値を分離し、原因ラベル・隠れ状態を診断器から遮断する。

### 修正順と受け入れ条件

1. **接続形式**：oracleアダプター、必須入力・単位・意味・範囲検査を追加し、現行pipelineと
   全中間状態・最終合否を一致させる。最終膜厚の`between`もr側の両側制約として維持する。
2. **学習接続**：流入状態も変化させた実験生成・学習を追加する。固定原料の19,683候補は
   回帰基準に残し、別ロット・流入状態・境界を含む未学習点で工程別／最終誤差と支持域を評価する。
3. **確率接続**：観測契約、要因別ばらつき、同時サンプルを追加し、最終合否のBrier score、
   予測確率と実際の合格割合、予測区間被覆率を独立データで検証する。各指標の対象を記録する。
4. **全体調整**：必須制約と設備前提を揃え、個別Bestと全体調整を同じ候補・予算で比較する。
   NG原因推定・後戻り実験はこの後の別段階とする。

物理式・指標・分布・制約を変える場合はモデル／設定版とハッシュを更新し、旧基準値を保存します。
現行22テストは基礎oracleの回帰に使い、上記の未実装機能を保証するテストとは扱いません。

## モデルの位置付け

各 `physics_model.py` は、熱・物質移動、キャピラリー数、Arrhenius型反応など、対象現象の支配因子を残した決定論的な物理縮約モデルです。同じ入力には常に同じ出力を返し、実機校正済みのCAEやデジタルツインではありません。係数・適用範囲・品質式は、最適化機能と工程接続を検証するための明示的なベンチマーク仮定です。

塗工、乾燥、熱硬化はそれぞれ `evaluate_model()` で単体利用できます。全入力はNumPyのscalar／配列に対応し、共通形状へbroadcastされます。`pipeline.evaluate_line()` は塗工出力を乾燥へ、乾燥出力を硬化へ渡し、最終仕様と `quality_margin`、`feasible` を返します。

## 決定論oracleとロバスト性評価

物理モデルの出力は決定論oracleです。工程条件を変動させたロバスト性評価（Monte Carlo等）の乱数は、物理モデル本体とは分離して `robustness.py` 側で扱います。したがって、同じ中心条件の真値を再評価でき、乱数によるばらつき評価と物理式の正解値を混同しません。

工程間の主な接続状態は、湿潤膜厚、固形分率、膜厚変動、残留溶剤、内部応力、欠陥指数です。各工程の `manifest.json` は操作条件、流入状態、出力の名前・単位・適用範囲・説明を記録します。

## CLI

リポジトリ直下から実行します。`evaluate-line` は原料状態を省略した場合、
粘度1.6 Pa·s、固形分率0.50、気泡率0.005の基準原料を使います。

```powershell
python -m multistage_validation.run list

python -m multistage_validation.run evaluate-stage coating --set `
  coating_gap_um=210 line_speed_m_min=18 web_tension_n=100 `
  incoming_viscosity_pa_s=1.6 incoming_solids_fraction=0.5 incoming_bubble_fraction=0.005

python -m multistage_validation.run evaluate-line --set `
  coating_gap_um=210 line_speed_m_min=18 web_tension_n=100 `
  air_temperature_c=90 air_speed_m_s=5.5 residence_time_min=13 `
  oven_temperature_c=140 hold_time_min=60 nip_pressure_mpa=0.325

python -m multistage_validation.run audit --samples 512 `
  --output multistage_validation/results/reference_audit.json
```

`evaluate-stage` は個別工程の操作条件と流入状態、`evaluate-line` は3工程を
通した全中間状態と最終合否をJSONで返します。`audit` は9操作条件×各3水準の
19,683候補を評価し、個別Best連結と全体調整候補、再現可能な良品確率を保存します。
既存の出力パスは誤上書きを避けるため拒否します。

## テスト

```powershell
python -m unittest discover -s multistage_validation/tests -t . -p "test*.py" -v
```

次を自動検査します。

- 各工程の単体テスト（物理的な傾向、境界、有限性、決定論性）
- scalar／vector／多次元配列のbroadcast契約
- 範囲外、NaN、Inf、形状不一致の入力拒否
- 塗工 → 乾燥 → 硬化の接続値が正しく伝播すること
- 個別Best連結が最終NGになり得ることと、全体調整条件の良品率改善
- ロバスト性乱数評価とoracle真値の分離・再現性
- 原因工程が既知のドリフト介入シナリオ
- 最終仕様、`quality_margin`、`feasible` の監査

既存 `validation/` のテスト・CLIとは別に実行できる構成を維持します。

確定した基準値と検証範囲は [`VALIDATION_REPORT.md`](VALIDATION_REPORT.md) を参照してください。

## 現在の対象範囲

このパッケージは物理oracleと比較用の粗い全体予測空間を提供します。学習済みv004 bundleの
合成、未学習4,096条件での最終予測、既知NGの工程順位付けと全工程回復は
[`r001_diagnostic_validation.py`](r001_diagnostic_validation.py)で検証できます。詳細結果は
[`r001_diagnostic_validation.json`](results/r001_diagnostic_validation.json)です。v003への
自動接続、潜在原因の同定、追加実験の選択はまだ実装していません。

r001の連結ウィンドウ断面は[`connected_window_validation.py`](connected_window_validation.py)で
物理oracle境界と照合します。実世界校正を合否条件に含めず、完全観測の決定論oracleに対して、
推定範囲が危険側へはみ出さないことと、真の許容範囲をどの程度残すかを別々に評価します。
独立した連結残差校正・方式選択データを各4,096点用いた片側残差方式では、危険側はみ出し0、
平均oracle窓回収率80.7%、走査点のFP 0でした。平均のみ／バッファ込み／支持度込みの縮小要因も
分離して保存します。[`window_center_joint_validation.py`](window_center_joint_validation.py)は、
窓中心選択によるoracle対称余裕の改善と、9変数同時変更4,096点・512頂点・二変数断面を独立oracleで
照合します。`rho`箱では予測側のFP 0、FN 88であり、有限標本検証であって連続領域の保証ではありません。
`incoming_state` と操作可能な `controls` をmanifestで分離しているため、将来の
個別最適化・ロバスト最適化・後戻り実験選択で役割を混同せず利用できます。
